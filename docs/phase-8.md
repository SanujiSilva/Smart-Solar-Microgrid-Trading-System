# Phase 8 completion record

## Delivered scope

Implemented the reservation lifecycle in the ASP.NET Core API. Active prosumers can create reservations against open station slots, view their own reservations, update eligible energy amounts, and cancel eligible reservations. Backoffice users and Grid Operators can view reservation details and pending reservations.

The API derives the prosumer NIC from the authenticated account and never trusts a client-supplied NIC. Reservation date/time is derived from the selected slot start time. New reservations are accepted only when the slot starts after the current server time and no later than seven days from it.

Updates and cancellations are allowed only for `PENDING` or `APPROVED` reservations with at least 12 hours remaining before the slot. Terminal states cannot be changed. A prosumer can only access their own reservation records.

Slot capacity is reserved with an atomic MongoDB conditional update. Creation requires an `OPEN` slot with enough available capacity. Updates atomically apply only the amount difference, and cancellation releases the reserved amount. If the reservation write fails after a capacity change, the service compensates by restoring the prior capacity.

Reservation codes are generated by the API using cryptographically random bytes. QR token generation and verification remain Phase 9 scope; no bearer QR value is returned by these endpoints.

## Manual testing

1. Create an `OPEN` slot whose start time is between now and seven days from now.
2. Log in as an active Prosumer and create a reservation below the slot’s available capacity.
3. Confirm the slot’s available capacity decreases and the response status is `PENDING`.
4. Attempt a reservation beyond seven days or above available capacity and confirm `400`/`409`.
5. Update the energy amount while more than 12 hours remain and verify only the capacity difference is applied.
6. Attempt update/cancellation inside 12 hours and confirm `409 Conflict`.
7. Cancel an eligible reservation and verify capacity is restored and status becomes `CANCELLED`.
8. Try accessing another prosumer’s reservation and confirm `403 Forbidden`.
